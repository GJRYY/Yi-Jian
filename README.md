# 衣见｜购物决策搭子

从纯前端 Demo 升级为「前端 + Node 后端」的本地 Web 应用。第一阶段已完成：
真实商品添加 / 链接解析 / 图片上传 / 资料确认 / 规则决策分析，并保留原有 Demo 体验。

## 目录结构

- `yijian-v3.html`：主页面（保留原 Demo，同时包含「添加真实商品」流程）
- `server.js`：后端入口
- `src/`：后端代码
  - `routes/`：商品、上传、决策、偏好提取等接口
  - `rules/engine.js`：规则决策引擎（从 Demo 移植）
  - `rules/derive.js`：从已确认字段推导评分（只做关键词推导，不编造）
  - `parsers/`：商品链接解析（通用页面适配器 + 平台判断）
  - `ssrf-guard.js`：服务端请求安全防护（禁内网、禁元数据地址、限大小、限时）
- `test/`：自动化测试（引擎、SSRF、API 集成）
- `data/`：本地数据（运行后生成，已被 Git 忽略）
  - `products.json`：商品资料
  - `uploads/`：上传的商品图片

## 本地启动

```bash
cd /Users/gjry/Desktop/Codex/yijian
npm install     # 首次运行
npm start       # 启动后端（默认 http://localhost:3000）
```

然后打开浏览器访问 `http://localhost:3000`：

- 「添加真实商品，帮我决策」：真实商品流程（需要后端运行）。
- 「DEMO体验」：原 Demo（固定示例商品，不需要后端）。

开发时可用 `npm run dev`（改动后端自动重启）；测试用 `npm test`。

## 快速测试一件真实商品

1. 启动后端后打开 `http://localhost:3000`，点「添加真实商品，帮我决策」。
2. 点「添加商品」：粘贴商品链接点「解析链接」（淘宝、小红书等需要登录的平台会明确提示不支持，请用截图或手动填写），或上传商品截图，再手动补充名称和价格。
3. 保存后点「查看并确认」，核对每个字段的来源标注（自动获取 / 你填写的 / 待补充），点「确认商品信息，继续」。
4. 确认完所有商品后「确认完成，进入问答」，按步骤回答场景、纠结点、优先级、衣橱、预算和雷区。
5. 查看结果页：推荐结论、组合总价、预算剩余、匹配 / 冲突 / 未知信息、横向比较。点「修改我的偏好」调整预算等条件后会重新分析。

## 数据与隐私

- 商品资料保存在 `data/products.json`，上传图片保存在 `data/uploads/`，都在本机项目目录内。
- 删除商品时会同步删除其本地上传的图片；整个 `data/` 目录删除即清空全部数据。
- 密钥只放在 `.env`（已被 `.gitignore` 忽略，不会提交到 Git）。参考 `.env.example`。
- 商品链接解析只发起服务端请求，并对本机 / 内网 / 云元数据地址做了拦截。

## 模型服务（第二阶段）

模型调用尚未接入（第一阶段只需要规则分析，不配置也能完整使用）。配置 `.env` 中的
`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 后，第二阶段将用于偏好理解和个性化解释。

## 当前限制

- 淘宝 / 天猫 / 1688 / 小红书页面需要登录或有反自动化机制，链接解析会明确返回
  「不支持」并引导手动填写；不会绕过登录、验证码或访问控制。
- 其他网页只解析可公开读取的标题、图片、价格和结构化数据，读不到就标注「待补充」。
- 单用户本地使用，无账号和多租户。
