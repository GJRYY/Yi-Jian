# 衣见｜购物决策搭子

一个帮助你做衣服购买决策的本地 Web 应用：把你正在犹豫的真实商品加进来，结合穿着场景、
衣橱情况和预算，用可验证的规则告诉你「哪件更适合、为什么、有什么冲突、还缺什么信息」，
该不买的时候也会直说「先别买」。

## 1. 项目解决什么问题

购物车里几件衣服都很喜欢，却不知道哪件值得买？衣见解决的是「下单前的纠结」：

- 不只看参数，而是把商品放进你真实的穿着场景里比较；
- 结合预算、衣橱重复情况和你的硬性要求，而不是只给一个模糊的「都很好」；
- 区分「已确认信息」「推导结论」「未知信息」，缺资料就如实标出来，不替你编答案；
- 尊重选择：推荐留下、建议淘汰、也可以建议一件都不买。

## 2. 主要功能

- **真实商品建档**：手动填写，或粘贴商品网页链接自动提取公开信息，或上传商品截图
  （JPG / PNG / WebP，最大 5MB）；每个字段都标注来源（自动获取 / 你填写的 / 待补充）。
- **资料确认环节**：逐字段核对商品资料，只有确认后的商品才会进入决策分析。
- **规则决策引擎**：预算硬限制（严格 / 可小幅超出 10% / 不设上限）、组合总价与剩余金额、
  场景匹配、优先条件匹配、衣橱重复、不可接受条件、冲突与未知信息识别。
- **问答流程**：场景与穿着频率、纠结点、优先级、衣橱情况、预算、雷区六步，可随时修改并重新分析。
- **结果页**：推荐结论、候选商品卡片、总价与预算状态、关键理由、匹配点、冲突点、
  横向比较、未知信息清单。
- **商品链接解析**（服务端执行）：读取公开网页的标题、图片、价格与结构化商品数据；
  带防 SSRF 保护（拒绝本机、内网、云元数据地址），对淘宝 / 天猫 / 1688 / 小红书等
  需要登录或有反自动化机制的平台明确返回「不支持」并引导手动填写，绝不绕过访问控制。
- **原 Demo 保留**：6 件示例商品的演示流程仍在，与真实商品数据完全隔离。

## 3. 安装方法

需要 Node.js 18 或更高版本。

```bash
cd yijian
npm install        # 安装依赖（express、multer）
cp .env.example .env   # 可选：需要调整端口或配置模型时才需要
npm start          # 启动后端，默认 http://localhost:3000
```

不配置任何密钥也能完整使用规则分析；`.env` 只在第二阶段接入模型时使用
（`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`）。

开发时可使用 `npm run dev`（改动后端自动重启），运行测试用 `npm test`。

## 4. 使用方法

### 浏览器界面

1. 打开 `http://localhost:3000`，点「添加真实商品，帮我决策」；
2. 「添加商品」→ 粘贴链接点「解析链接」或上传截图，补全名称和价格 →「保存商品资料」；
3. 对每件商品点「查看并确认」，核对字段来源标注后「确认商品信息，继续」；
4. 全部确认后进入六步问答，最后查看结果页；点「修改我的偏好」可改预算等条件并重新分析；
5. 首页的「DEMO体验」走原演示流程，不依赖后端数据。

### 后端 API

所有接口以 JSON 交互，错误统一返回 `{ "error": { "code": "...", "message": "..." } }`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 服务与 AI 配置状态 |
| GET | `/api/products` | 商品列表 |
| GET | `/api/products/:id` | 单件商品 |
| POST | `/api/products` | 创建商品（名称、价格必填） |
| PATCH | `/api/products/:id` | 修改商品；改动过的字段来源标记为「用户填写」 |
| DELETE | `/api/products/:id` | 删除商品（同步删除其本地上传图片） |
| POST | `/api/products/:id/confirm` | 确认商品资料（确认后才可进入分析） |
| POST | `/api/products/parse-url` | 解析商品链接（服务端请求 + 防 SSRF） |
| POST | `/api/uploads` | 上传商品图片（multipart，字段名 `image`） |
| POST | `/api/decision/analyze` | 对已确认商品执行决策分析 |
| POST | `/api/preferences/extract` | 偏好提取（第二阶段；未配置模型返回 `not_configured`） |

## 5. 输入输出示例

### 输入：两件已确认的商品

```json
[
  {

    "price": 599,
    "color": "驼色",
    "material": "羊毛混纺",
    "style": "通勤 / 百搭",
    "scenario": "日常通勤",
    "care": "dryClean"
  },
  {
    "name": "水洗蓝牛仔夹克",
    "price": 459,
    "color": "水洗蓝",
    "material": "牛仔",
    "style": "休闲 / 街头",
    "scenario": "日常休闲",
    "care": "machine"
  }
]
```

### 输入：用户需求（问答结果）

```json
{
  "scenario": "commute",
  "frequency": "weekly4",
  "concerns": ["fabric"],
  "priorities": ["texture", "value"],
  "topPriority": "texture",
  "budget": "1000",
  "budgetMode": "strict",
  "wardrobe": [],
  "dealbreakers": []
}
```

### 输出：`POST /api/decision/analyze`（真实引擎返回，节选）

```json
{
  "type": "recommend",
  "headline": "我建议你只留下这一件",
  "keep": [{ "name": "水洗蓝牛仔夹克", "price": 459 }],
  "totalPrice": 459,
  "reasons": [
    "水洗蓝牛仔夹克在你选择的日常通勤场景里最不容易出错。",
    "你优先看重的面料质感与耐穿程度和性价比，它整体接得住。",
    "总价 ¥459 在 ¥1,000 预算内，剩余 ¥541。"
  ],
  "comparison": [
    { "name": "驼色羊毛风衣", "price": 599, "matchPercent": 67, "final": "淘汰" },
    { "name": "水洗蓝牛仔夹克", "price": 459, "matchPercent": 70, "final": "留下" }
  ],
  "analyses": ["每件商品的字段、匹配点、冲突点与未知信息（此处省略）"]
}
```

### 输出：预算无法满足时（预算 400，严格模式）

```json
{
  "type": "none",
  "headline": "这次我建议你一件都别留",
  "keep": [],
  "totalPrice": 0,
  "reasons": [
    "你比较的商品都踩中了至少一个硬性条件，与其将就，不如先都不买。",
    "你最看重的需求和这些商品没有形成明确匹配，硬留一件很可能后悔。",
    "清空购物车不是失败，说明这次筛选帮你省下了一次不必要的下单。"
  ]
}
```

硬性限制（如严格预算）不会被「推荐」覆盖；缺少关键资料时相应条目显示为「未知」，不会编造结论。

## 目录结构

```
yijian/
├── yijian-v3.html        # 前端主页面（Demo + 真实商品两条流程）
├── server.js             # 后端入口
├── src/
│   ├── routes/           # 商品、上传、决策、偏好提取接口
│   ├── rules/            # 规则引擎与字段推导
│   ├── parsers/          # 商品链接解析（平台适配）
│   ├── ssrf-guard.js     # 服务端请求安全防护
│   └── storage.js        # 本地 JSON 文件存储
├── assets/products/      # Demo 示例商品图片
├── test/                 # 自动化测试（引擎、SSRF、API 集成）
└── data/                 # 运行后生成，已被 .gitignore 忽略
    ├── products.json     # 商品资料
    └── uploads/          # 上传的商品图片
```

## 数据与隐私

- 商品资料和上传图片只保存在本机 `data/` 目录，删除商品会同步删除其本地上传图片；
  删除整个 `data/` 目录即清空全部数据。
- 密钥只放在 `.env`（已被 `.gitignore` 忽略，不会进入 Git 或前端代码）。
- 链接解析只由服务端发起，并拦截本机、内网与云元数据地址，限制响应大小与超时时间。

## 当前限制

- 淘宝 / 天猫 / 1688 / 小红书无法匿名解析（有意为之），请使用截图或手动填写；
- 其他网页只能提取可公开读取的信息，读不到的字段一律标注「待补充」；
- 模型服务（偏好理解、个性化解释）为第二阶段功能，当前使用规则分析；
- 单用户本地使用，无账号与多租户。
